# Маркетинговый агент — ядро (фаза 1)

Прототип самооптимизирующегося рекламного агента на моке Яндекс Директа:
**поиск (CPC) + РСЯ (CPM)**, единая цель — **целевой CPA** для обоих типов инвентаря.

Источник истины — спецификация: [`spec/spec_marketing_agent_core.md`](spec/spec_marketing_agent_core.md) (ред. 2).
Числовые значения параметров — `src/config.py`.

## Что внутри (по спеке §0–§12)

- Канонная модель данных (§2) и KPI-движок: сглаженные CTR/CR (Beta), Wilson-интервалы,
  CPA/eff/границы для search и network (§3).
- Контракт адаптера площадки (§4) и мок-симулятор `MockYandexDirect` с двумя моделями
  аукциона (CPC/CPM) и «оракулом» на истинных параметрах (§5).
- Ядро оптимизации: статистический гейт, контроллер ставок → CPA, Thompson-bandit
  аллокация бюджета единым пулом, prune/scale (§6).
- Guardrails-инварианты (§7), цикл-оркестратор (§8), память + лог решений (§9),
  объяснимость каждого решения (§10).
- Демо-прогон с бейзлайнами (равный бюджет + фикс. ставка; оракул) и артефактами
  приёмки (§12).

Вне ядра (фаза 2+, §13): боевой API, другие площадки, LLM-генерация.

## Установка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск

```bash
python run.py     # демо-прогон агент vs baseline vs oracle; артефакты в dashboard/
pytest -q         # тесты: KPI, Wilson, guardrails, оптимизатор, детерминизм
```

## Детерминизм

Все прогоны воспроизводимы: глобальный `SEED` в `src/config.py`, RNG тика мока —
чистая функция от `(SEED, tick)`. Bandit-сэмплинг использует отдельный поток RNG.

## Структура

```
src/
  types.py          канонная модель (§2)
  config.py         все параметры (§11) — источник истины по значениям
  kpi.py            KPI, Wilson, CPA/eff/границы (§3)
  adapter.py        контракт PlatformAdapter (§4)
  mock_direct.py    MockYandexDirect: два аукциона, скрытые параметры (§5)
  optimizer.py      гейт, контроллер ставок, bandit-бюджет, prune/scale (§6)
  guardrails.py     инварианты (§7)
  memory.py         состояния, накопление счётчиков, лог решений (§9, §10)
  orchestrator.py   цикл tick (§8)
  oracle.py         оптимум на истинных параметрах (приёмка vs oracle)
  baselines.py      бейзлайн: равный бюджет + фикс. ставка
run.py              демо-прогон + сбор артефактов (§12)
dashboard/          выходные графики/таблицы (генерируются)
tests/              pytest
```
